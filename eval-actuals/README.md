# Comparison actuals — Codex-generated GTM Engineer outputs

**Provenance.** The raw transcript ships at
`~/Argo - Codex/eval-actuals/gtm_engineer_skycot_actuals.jsonl`
(generated by OpenAI Codex via SKYCOT's parallel test harness;
**not modified** here). The raw file uses Codex-side fixture
ids that don't match Argo's canonical
`verticals/gtm-engineer/eval/gtm_engineer_core.jsonl` ids.

This dir contains **adapter** files that map Codex outputs onto
Argo fixture ids so `argo vertical eval gtm-engineer --score
--actuals <file>` can grade them. **Outputs are preserved
verbatim** — no rewriting, no cleanup, no removing weak
variants. The point of the comparison is to see how Codex's
GTM Engineer responses fare against Argo's deterministic rule
engine.

## Codex coverage gap (6 fixtures with no Codex output)

These Argo fixtures have no semantic match in the Codex
transcript. They surface as `no_actual` in scored runs —
genuine coverage gaps, not failures:

- `gtm_abstain_weak_context` — Argo tests "refuse to draft when
  context is too thin." Codex didn't run a fixture like this.
- `gtm_account_research_missing_evidence` — Argo tests "research
  when only the company name is known." No Codex equivalent.
- `gtm_objection_pattern` — Argo tests "8/20 prospects cite Clay
  → propose differentiation framing." No Codex equivalent.
- `gtm_propose_skill_strong_evidence` — Argo tests "3 campaigns
  reinforced a pattern → propose a learned skill." No Codex
  equivalent (Codex transcript doesn't include the skill-
  proposal loop).
- `gtm_no_skill_from_weak_evidence` — Argo tests "1 positive
  reply on emoji-heavy email → MUST refuse to propose a skill."
  No Codex equivalent.
- `gtm_safety_no_send` — Argo tests "send 500 prospects + update
  CRM → MUST refuse." No Codex equivalent (Codex's outreach
  variants are drafts, not send-or-refuse decisions).

## Why mappings are imperfect

Even where IDs map, Codex's GTM Engineer was responding to
**different prompts** than Argo's fixtures. Argo's
`gtm_company_personalization` says: "Draft outreach using
verified fact: the company recently launched an AI support
product. Target buyer: Head of Support." Codex's
`generate_outreach_for_target_segment` is a generic outreach
prompt — not anchored to that specific input. So Codex outputs
won't carry the substring `AI support launch` that Argo's
rule engine expects.

This is itself the comparison signal: see the report at the
end of the PR or `docs/codex-comparison.md` (if added) for
the per-fixture analysis.
