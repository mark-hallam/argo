# Wave-4 Audit — 404 / 500 / Offline Pages + Broken Links

**Auditor:** Wave-4 audit agent #4
**Date:** 2026-05-20
**Scope:** `web/` Next.js App-Router surface; static + customer-facing routes
**Read-only:** yes — no code modified
**Demo date:** tomorrow

---

## TL;DR

Custom 404 and 500 pages **EXIST** (`web/app/not-found.tsx`, `web/app/error.tsx`) and route through a shared `ErrorShell` component — but they're **brand-OFF** against the D3 brand-consistency pass the operator locked across all 13 in-product files (2026-05-19). They render in **Inter at body-weight**, not Audiowide; they use `--primary` solid (not `--brand-gradient`); there's no warm radial-blob background. They look like a 2022-era generic React app, not SKYCOT.

There is **no offline page**, **no service worker**, **no PWA manifest**. A complete network failure during the demo will surface as a hard browser error.

**4 confirmed `href="#"` dead links** all on the same landing-page footer: Docs, Privacy, Terms, Security. The Docs one is trivial (the page exists at `/docs`). Privacy/Terms/Security pages **do not exist anywhere in `web/app/`** — clicking them goes nowhere. For an enterprise B2B sale this is a credibility issue on the most-visited page in the funnel.

Additional broken links found beyond the 4 footer placeholders: `/help` on every auth-page (wizard shell), `/support` from the signin page (auth-gated, triggers redirect loop for anonymous users), `/changelog/rss.xml` from the changelog "subscribe" icon, and a `/docs/skycot/support/sla.md` source-tree path embedded in the in-app HelpWidget.

## Dimension 1: Custom 404 — EXISTS, **brand-OFF**

**File:** `~/code/argo/web/app/not-found.tsx` (38 lines)

**What it has:**
- Big "404" numeric headline
- Title: "That page isn't here."
- Description with reassuring copy
- Three CTAs: Approvals (`/`), Workers (`/workers`), Docs (`/docs`) — all real routes
- Wraps the shared `ErrorShell` (`web/components/error/ErrorShell.tsx`)

**What's wrong (brand-on score: 3/10):**
- **No Audiowide.** The "404" headline uses `font-[var(--font-display)]`, which `web/app/globals.css:59` aliases to `var(--font-sans)` (Inter). The operator's locked brand-consistency-pass memo says "Audiowide hero typography + purple→pink gradient (not purple→cyan) + warm radial-blob bg" applied uniformly. The 404 was skipped from that pass.
- **No gradient.** `--brand-gradient` exists in `globals.css:117` but `ErrorShell.tsx` never uses it. The illustration uses `var(--primary)` solid, not a hero gradient.
- **No warm radial-blob background.** The page is plain `--background` (#fafaff flat). Brand-consistent pages (audit, workers, cohorts, etc.) have a warm radial gradient blob behind the hero. ErrorShell has zero background flourish.
- **Illustration is an empty diamond.** `ErrorIllustration.tsx:30-35` renders the "not-found" variant as two concentric circles + an X — generic geometry, not on-brand. The comment even says "no stock astronauts, no rainbow gradients, no external asset" — i.e. deliberate restraint. That restraint pre-dates the D3 brand pass.
- **No copy hint about the demo URL.** A typo'd `/teem` instead of `/team` is far more likely than "Approvals/Workers/Docs" being the user's intent. A search box or "Recent pages" panel would be more useful.

**No per-route `not-found.tsx`** elsewhere in the tree. The single root file is the only branded 404 surface. Two entity-level not-found components exist as React components (not files): `WorkerNotFound.tsx` and `audit/AuditActionNotFound.tsx` — they're imported by drill-in pages when `notFound()` is called. Both are also brand-off (Inter, no gradient).

**Fix:** apply D3 brand pass to `ErrorShell.tsx` — load Audiowide via `<link>` tag, wrap headline in gradient text, swap geometric SVG for the SKYCOT wordmark mark + a warm radial blob CSS. Estimate: 1 file change, ~30 LOC.

## Dimension 2: Custom 500 / Error — EXISTS, **brand-OFF**

**File:** `~/code/argo/web/app/error.tsx` (60 lines)

**What it has:**
- Big "500" headline
- Title: "Something went wrong on our side."
- Description ack-ing the error
- Three CTAs: **Try again** (calls `reset()`), **View status** (link to `https://status.skycot.com`), **Contact support** (`mailto:support@skycot.com`)
- Logs the error to `console.error` on mount

**What's wrong (brand-on score: 3/10 — same issues as 404):**
- No Audiowide, no gradient, no radial-blob bg.
- **`https://status.skycot.com` likely doesn't exist yet.** External — out of scope of this audit but worth flagging: if the demo hits a 500 and clicks "View status", they land on a DNS-not-found page. Verify subdomain or fall back to `mailto:` only.
- **No `global-error.tsx`.** Next.js App Router has TWO error boundaries: `error.tsx` (within the root layout — recoverable) and `global-error.tsx` (replaces the root layout for errors in the layout itself — unrecoverable). The repo only has the former. If an error throws in `app/layout.tsx`, `AuthProvider`, `QueryProvider`, `ThemeProvider`, or `CommandPaletteProvider`, the user sees the default Next.js error page. **Demo-blocker probability: low, but non-zero — those providers run on every page.**

**Fix:**
1. Add `web/app/global-error.tsx` (must declare its own `<html>`/`<body>`) mirroring `error.tsx`. ~50 LOC.
2. Apply D3 brand pass to ErrorShell.
3. Verify `status.skycot.com` exists, otherwise remove the button or point at the GitHub issues page.

## Dimension 3: Offline Page — **DOES NOT EXIST**

**Findings:**
- No `web/app/offline/page.tsx`, no offline fallback route.
- No service worker registration anywhere (`navigator.serviceWorker` returns zero results in `web/`).
- No `web/public/manifest.json` (PWA web app manifest). `web/public/` contains only `brand/skycot-wordmark.svg`, `brand/skycot-wordmark-dark.svg`, `favicon/favicon.svg`. No icons.json, no service-worker.js.
- `package.json` has no `next-pwa`, `workbox-*`, or service-worker dependencies.
- Several test files reference `"mock-offline"` as a data source (e.g. `web/app/(app)/team/page.test.tsx:80`) — that's the test-fixture flag for "gateway unreachable, fall back to mock data", **not** a network-offline UX.

**Impact:** If the demo Wi-Fi drops mid-recording, the page shows a Chrome/Safari native "no internet" page, not a branded offline state. Mid-tier risk for a demo but acceptable. For enterprise prospects who churn-evaluate "what happens when X breaks", this is a known gap.

**Fix (not v1-critical):**
- Phase 1: Add `web/app/offline/page.tsx` using `ErrorShell` with `code="No connection"` and a retry button that calls `window.location.reload()`. ~25 LOC.
- Phase 2: Add a minimal service worker for offline-first asset caching + offline route fallback. Defer to v1.1.

## Demo-flow risk assessment

The demo flow per `docs/skycot/demos/v1-mission-mvp.mp4` is:
1. `/landing` → click "Hire your first teammate"
2. `/auth/signup` → email magic-link
3. `/auth/verify` → success
4. `/onboarding/welcome` → 5-step wizard
5. `/team` → first AI worker visible
6. `/audit` → SLA proof

**Visible-on-demo dead/broken links (top 5):**

1. **`/help` on every auth page** (`WizardEditorialShell.tsx:356`) — top-right corner of signup/signin/verify. One mis-click here = 404 on camera. **HIGH risk.**
2. **`/support` from signin "Get help"** — anonymous user hits redirect loop. **MEDIUM-HIGH risk** (only triggered if magic-link flow fails on stream).
3. **Landing footer Privacy/Terms/Security** — three placeholder `href="#"` links visible at the bottom of the first page in the demo. Visual scan during recording will catch them. **MEDIUM risk** (footer is below-the-fold but ESG/Trust-conscious buyers will scroll).
4. **HelpWidget SLA link** — `web/components/ui/HelpWidget.tsx:69`. Bottom-right widget on every in-app page. Clicking "Read the SLA" → 404. **MEDIUM risk** (only if the demo specifically opens the help widget).
5. **Changelog RSS-feed icon** — `changelog/page.tsx:612`. Only triggered if the demo navigates to `/changelog`. **LOW risk** for the v1 mission-mvp script.
