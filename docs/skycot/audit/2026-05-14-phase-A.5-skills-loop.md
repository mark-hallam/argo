## Drift findings (parallel skill-lifecycle paths)

- **Mechanical path** (single trajectory → SkillCandidate via `from_cu_trajectory`): lives in `argo-executor-computer-use/src/learn.rs` + `argo-skill/src/learn.rs`. Low quality; ships immediately.
- **Dreams-distilled path** (cohort ≥3 → `distill_cohort`): lives in `argo-skill/src/dreams_distillation.rs`. High quality; requires LLM call; shipped for workspace-wide.
- **Forge optimization path**: exists in stub form only; never completes a full cycle.
- **Per-worker learning**: never implemented; feedback table populated but cron never fires.

**Result**: 3-4 partially-overlapping learning paths, none complete.

## Seam misalignment

1. **Library + workspace split incomplete.** `LayeredLookup::with_library` exists in `argo-skill/src/library.rs`, but `argo-agent-runner/src/turn.rs` never calls it. The H-4b TODO at `crates/argo-cli/src/handlers/gateway/routes_skills.rs:30` documents the gap but no brief had been authored.
2. **Marketplace discovery vs. skill loading disconnected.** `marketplace::search` (argo-skill/src/marketplace.rs) is a user-facing catalog. `LayeredLookup::with_library` is a runtime loader. The two are not connected; no code ties a marketplace skill to a worker's library store.
3. **Skill provenance not propagated to runtime.** Published skills carry trust_grade + provenance, but marketplace-loaded skills are not distinguished from workspace skills once in the system prompt. No "origin: marketplace" annotation.

## Architectural call: do we need a new orchestrator crate?

**NO. argo-skill is already the lightweight hub.**

The 5 crates are sufficient if:
- argo-skill absorbs the wiring (Brief A in agent-runner; integration-test in argo-skill).
- argo-skill/src/learn.rs is the entry point for all propose-for-review calls. ✅ Already true.
- argo-skill/src/publish.rs is the exit point. ✅ Already true.
- argo-skill owns the eval gate. ✅ Already true.

Adding a parallel `argo-skill-orchestrator` crate would be the exact drift pattern the playbook warns against. Use argo-skill as the orchestrator hub; add the 100-LOC `run_skill_loop_tick` helper there if a centralized entry point becomes desirable post-v1.
