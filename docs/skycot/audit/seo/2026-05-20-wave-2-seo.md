# Wave-2 SEO + META + OPEN GRAPH AUDIT — SKYCOT public marketing pages

**Date:** 2026-05-20
**Auditor:** Wave-2 audit agent #4 (SEO/meta/OG)
**Scope:** read-only inspection of `web/app/**` for SEO, meta, OG, Twitter Card, JSON-LD, canonical, sitemap, robots
**Method:** static read of `layout.tsx` and `page.tsx` files (dev server not running; no `curl` against live HTML — Next.js renders deterministically from the `Metadata` exports, so static read is sufficient for completeness)

---

## TL;DR

**Overall SEO score: 3 / 10.**

The text content of titles + descriptions is on-brand and well-written. Everything else is missing:
- **No OG image anywhere.** No `opengraph-image.tsx` route, no static PNG in `/public`, no `/api/og` endpoint. Every social share will render as a **plain blue card with text only** — embarrassing for a $1k+/month enterprise product.
- **No `sitemap.xml`. No `robots.txt`.** Search engines have nothing to crawl from. Both are zero-effort wins (Next.js has built-in `sitemap.ts` and `robots.ts` conventions).
- **No JSON-LD structured data anywhere.** No `Organization`, no `Product`, no `FAQPage`, no `Article`.
- **No canonical URLs on any page.** `alternates.canonical` is absent everywhere.
- **`/auth/signup` and `/auth/verify` inherit `"Sign in"` as the title** because they are client components that can't export metadata, and `auth/layout.tsx` hardcodes "Sign in". Browser tabs lie about which page the user is on.
- **No `twitter:site` handle** (only `creator`). Twitter Card validator will warn.
- **No `themeColor` or `viewport` metadata** — minor, but affects mobile Safari address bar colour.

The product is enterprise-grade; the metadata layer is hobby-project-grade.

## 6-dimension findings

### 1. `<title>` — partial

Root template: `"%s · SKYCOT"` (good). Root default: `"SKYCOT — Hire your first AI teammate"` (good — 41 chars, brand + value prop).

- **POLISHED:** `/landing` ("Hire your first AI teammate · SKYCOT"), `/compare` ("SKYCOT vs Zapier, n8n, Crew.ai, Lindy · SKYCOT" — 47 chars, keyword-rich, great)
- **WEAK:** `/pricing`, `/customers`, `/changelog`, `/docs` — single-word titles. "Pricing · SKYCOT" gives a search engine no reason to rank you over the 100k other "Pricing" pages. Should be e.g. "Pricing — per-teammate billing · SKYCOT" or "Pricing & plans for AI teammates · SKYCOT".
- **BUG:** `/auth/signup`, `/auth/verify`, `/auth/check-email` all render `"Sign in · SKYCOT"` because:
  - `web/app/auth/layout.tsx:5` hardcodes `title: "Sign in"`
  - The four pages under it are all `"use client"` components (e.g. `web/app/auth/signup/page.tsx:1`), so they **cannot** export `metadata` (Next.js disallows it on client components)
  - Result: `/auth/signup` tells the browser tab and the search engine that it's a sign-in page. That's a real SEO + UX bug.

### 2. `<meta name="description">` — mostly polished, one bug

- **POLISHED on:** root, landing, compare, pricing, customers, changelog, docs, signin. All unique, all on-brand, all under 155 chars except root (which is 261 chars — over the limit, will be truncated in SERPs).
- **BUG:** `/auth/signup`, `/auth/verify`, `/auth/check-email` all show the signin description because of the same client-component issue. The signup page is a public marketing entry-point — having its description say "Magic-link sign-in to your SKYCOT workspace" is wrong.
- **NIT:** root description (`web/app/layout.tsx:30-31`) is **261 chars** — Google truncates at ~155. Trim by 40%.

### 3. Open Graph tags — partially defined, image entirely MISSING

What's set in `web/app/layout.tsx`:
- `og:type` = `"website"` ✅
- `og:url` = `"https://skycot.com"` ✅
- `og:title` ✅
- `og:description` ✅
- `og:site_name` = `"SKYCOT"` ✅
- `og:locale` = `"en_US"` ✅
- `og:image` ❌ **MISSING** — no `images: [...]` in the `openGraph` object, and no `web/app/opengraph-image.tsx` (Next.js convention) and no static `public/og-default.png`.

Per-page OG title/description overrides exist on every layout (landing, compare, pricing, customers, changelog, docs). None of them add an image either.

**Concrete impact:** Paste a SKYCOT link into Slack, LinkedIn, Twitter, iMessage, or Discord — the unfurl shows the title and description on a **plain background with no visual**. For a launch where the operator wants the "epic UX must go viral" register, this is the single biggest fixable embarrassment.

There is no PNG/JPG of any kind in `web/public/`:
```
web/public/
├── brand/skycot-wordmark-dark.svg
├── brand/skycot-wordmark.svg
└── favicon/favicon.svg
```

### 4. Twitter Card — defined, but no image and no `twitter:site`

`web/app/layout.tsx:54-60` sets:
- `twitter:card` = `"summary_large_image"` ✅ (good — wide card)
- `twitter:title` ✅
- `twitter:description` ✅
- `twitter:creator` = `"@skycot_ai"` ⚠️
- `twitter:site` ❌ **MISSING** — the Twitter Card validator specifically asks for `site` (the publishing account); `creator` is for individual author handles. Many parsers will warn or downgrade the card.
- `twitter:image` ❌ **MISSING** — falls back to OG image, which is also missing.

`summary_large_image` **without an image** is the worst combination — Twitter will downgrade to a tiny card or refuse to unfurl. (The handle `@skycot_ai` is also worth confirming the operator actually owns; not validated.)

### 5. Structured data (JSON-LD) — entirely MISSING

Grep results: zero `application/ld+json` script tags, zero `@context` JSON-LD blocks, zero `JsonLd` components in `web/`.

What's missing and where it should go:
- **`Organization`** — root layout. Adds the SKYCOT logo + sameAs links to Google's Knowledge Graph. ~15 lines of JSON, zero downsides.
- **`Product`** — landing. SKYCOT is a SaaS product; this lets Google show pricing + rating in SERPs.
- **`FAQPage`** — pricing (presumably has FAQ section) and any docs Q&A. This is the highest-impact one — FAQPage rich results show as expandable accordions directly in Google results and can double click-through.
- **`Article`** — each changelog entry. Even if the changelog is a single page, each `<article>` block could carry inline JSON-LD with the date.
- **`BreadcrumbList`** — docs and customer subroutes when those exist (none currently).

### 6. Canonical + robots — MISSING canonical, MISSING sitemap, MISSING robots.txt

- **Canonical URLs:** `grep "canonical\|alternates"` across `web/app/**` returns **zero results**. Every page is missing `alternates: { canonical: "..." }`. This is critical for `/auth` (parameter pollution from magic links creates infinite duplicate URLs) and for any page that might be reached via UTM-tracked links.
- **`robots` meta tag:** the root layout does set `robots: { index: true, follow: true, googleBot: {...} }` ✅. This is decent.
- **`sitemap.xml`:** **NOT FOUND.** No `web/app/sitemap.ts` (Next.js convention) and no static `web/public/sitemap.xml`. Search engines won't know about /pricing, /compare, /customers, /docs, /changelog unless they crawl them via links from /landing — which works but is fragile and slow to index.
- **`robots.txt`:** **NOT FOUND.** No `web/app/robots.ts` and no static `web/public/robots.txt`. Without one, Google still defaults to "crawl everything" (so it's not a blocker for indexing), but it's also where you point crawlers to your sitemap. Standard hygiene.

### Bonus findings

- **No `viewport` or `themeColor`** metadata exports. Mobile Safari address bar won't pick up the SKYCOT brand purple. Easy to add.
- **No `metadataBase`-aware OG image path** (would matter once an image exists).
- **`metadataBase` is set** to `https://skycot.com` ✅ — good, this means relative URLs in OG/Twitter resolve correctly. The infrastructure for richer metadata is in place; the content is just missing.
- **No `404` / `not-found` metadata** — `web/app/not-found.tsx` exists but doesn't export `metadata`. Hard 404s will inherit the root title.

## Worst page

**`/auth/signup`** is the worst. It's a public marketing entry-point (linked from /landing CTA, from /pricing CTA, from /compare CTA) and it currently:
1. Sets `<title>` to "Sign in · SKYCOT" — the browser tab tells the user they're signing in when they're actually signing up
2. Sets the description to magic-link-signin copy, not signup copy
3. Has no canonical (magic-link query params will spawn duplicate URLs)
4. Has no OG image
5. Has no per-page OG title/description override

A first-time visitor who pastes the signup link in Slack to recommend SKYCOT to a colleague sees an OG card that says "Sign in" with no image. That's the opposite of viral.

Tied for second-worst is the entire `/auth/` subtree (verify, check-email) for the same reason.

After the `/auth` bug, the **single weakest marketing page** is **`/pricing`** — single-word title, no FAQPage JSON-LD (which is the highest-ROI structured-data fix for any pricing page), no OG image.

## Top fix that improves multiple pages

**Add a single root-level OG image** — this is the highest-ROI fix in the whole audit because it solves the "embarrassing share preview" problem across all 10 pages in one change.

Two implementation options:
1. **Static PNG** — design once, ship to `web/public/og-default.png` (1200×630, SKYCOT wordmark + tagline + brand gradient), then add `images: [{ url: "/og-default.png", width: 1200, height: 630, alt: "SKYCOT — Hire your first AI teammate" }]` to the root `openGraph` block in `web/app/layout.tsx`. Cheapest fix.
2. **Dynamic `opengraph-image.tsx`** — Next.js convention. Create `web/app/opengraph-image.tsx` (and one per route for per-page variants like `web/app/compare/opengraph-image.tsx`) using `ImageResponse` from `next/og`. Renders on demand at build time. Slightly more work, but lets `/compare` ship "SKYCOT vs Zapier, n8n…" as an image with the brand gradient, and `/pricing` show the actual plans.

Either way, this single fix means every Slack/LinkedIn/Twitter/iMessage share gets a brand-on visual. The current state (no image at all) is the most-fixable embarrassment.

**Three other multi-page fixes ranked by ROI:**
1. Add `web/app/sitemap.ts` (Next.js convention; ~20 lines that list the 6 public routes) + `web/app/robots.ts` (5 lines that point to the sitemap). Indexable in a single afternoon.
2. Add per-page `alternates: { canonical: "..." }` to all 7 marketing layouts. ~7 one-line edits.
3. Fix the `/auth/*` title leak — extract the page-specific titles into a per-page `metadata` export, which requires either (a) making the signup/verify/check-email pages server components that wrap the existing client component, or (b) adding per-route nested layouts (`web/app/auth/signup/layout.tsx`, `web/app/auth/verify/layout.tsx`, `web/app/auth/check-email/layout.tsx`) each with their own `metadata` export. Option (b) is the lower-risk fix and is ~12 lines per route.

## Social-share preview verdict

**Embarrassing.** A SKYCOT link shared in Slack, LinkedIn, Twitter, Discord, iMessage, or Teams will render with:
- The correct title text
- The correct description text
- **A blank space where the image should be**, or a tiny site-icon-only card

For a product whose pitch is "epic UX, viral" and whose target customer is enterprise (where decision-makers absolutely DO judge by share previews), this is brand-off. The cheap fix (one PNG in `/public` + 5 lines in `web/app/layout.tsx`) takes social previews from embarrassing → brand-on.

After the OG image lands, the next round of polish (per-page OG image variants, sitemap, robots, canonical, JSON-LD) takes the SEO score from **3/10 → 8/10**.
