## TL;DR — overall demo-readiness perf score: 6 / 10

The Rust gateway is fast (TTFB sub-200ms on every page), the HTML payloads are small (45-105 KB), and the structural choices (React Query, App Router, `next/font` already in `layout.tsx`) are sound. **What pulls the score down is one recurring antipattern that affects every page on the demo path**: each route group reproduces its own Google-Fonts `<link>` block + `<style jsx global>` brand-token block, defeating the `next/font` setup already wired in `app/layout.tsx`. Compounding that: 60 of 99 app/ files are `"use client"`, half of which have **zero** state and could be Server Components. The `/compare` flash-of-unstyled-content is a direct consequence of this — fonts and CSS variables only attach after hydration, so the first paint is unstyled.

## The 5 dimensions

### 1. Client-bundle bloat — 60 of 99 (61%) `app/` files are `"use client"`

`rg -l '"use client"' web/app/ | wc -l` returns **60**. Total `.tsx` / `.ts` files in `web/app/`: **99**. That's a 61% client-component ratio.

**Pages with `"use client"` but ZERO state callsites** (no `useState`, `useEffect`, `useRouter`, `useContext`, `useReducer`, `useRef`, `onClick`, `onChange`, `onSubmit`):

| File | LOC | Hooks/handlers found |
|------|-----|----------------------|
| `web/app/landing/page.tsx` | 1090 | 0 |
| `web/app/compare/page.tsx` | 473 | 0 |
| `web/app/customers/page.tsx` | 635 | 0 |
| `web/app/docs/page.tsx` | 725 | 0 |
| `web/app/changelog/page.tsx` | 734 | 0 |
| `web/app/(app)/workers/[workerId]/overview/page.tsx` | 31 | 0 |

These six pages **should not** be client components. The first four are public marketing pages — purely declarative JSX with no interactivity. The worker overview page is a 31-line composition of three children; the page itself has no state. Removing `"use client"` from these six files is a 30-second edit per file (delete the directive line) and would let Next.js ship server-rendered HTML with **no JS hydration cost** for the page shell.

Only `pricing/page.tsx` (3 callsites) has any client-side state in the marketing folder.

**Demo-path pages that legitimately need `"use client"`** (verified — actual hook usage):

- `/` (Approvals) — 13 callsites (React Query, filter state, Radix popover)
- `/team` — 15 callsites (search + filter URL state)
- `/audit` — 14 callsites (filter chips + cursor pagination)
- `/workflows/templates` — 8 callsites (cohort filter)
- `/workflows/[v]/[n]/build` — uses `useState` + xyflow reactflow state — must be client
- `/skills` — 4 callsites (search input)

### 2. Duplicate font loading — 13 page files + 6 components reproduce the Google-Fonts `<link>` block

`next/font/google` is wired correctly in `app/layout.tsx` (Inter + JetBrains Mono with `display: swap`). Audiowide is NOT included there (Google Fonts doesn't have an official `next/font` entry, fair enough). **However**, 13 page-level files AND 6 shared components inject their OWN Google-Fonts `<link>` tags:

```text
web/app/(app)/settings/members/page.tsx
web/app/(app)/settings/page.tsx
web/app/(app)/skills/[skillId]/page.tsx
web/app/(app)/skills/page.tsx
web/app/(app)/workflows/[verticalId]/[name]/page.tsx
web/app/(app)/workflows/page.tsx
web/app/(app)/workflows/templates/[templateId]/page.tsx
web/app/(app)/workflows/templates/page.tsx
web/app/changelog/page.tsx
web/app/compare/page.tsx
web/app/customers/page.tsx
web/app/docs/page.tsx
web/app/landing/page.tsx
web/app/pricing/page.tsx
web/components/auth/AuthEditorialShell.tsx
web/components/auth/WizardEditorialShell.tsx
web/components/skycot/AppShell.tsx                       ← global app chrome
web/components/skycot/BrandLoudHero.tsx                  ← used by Team / Approvals / Cohorts
web/components/skycot/CommandPalette.tsx
web/components/skycot/worker/WorkerPersonalityCard.tsx
```

The most egregious case is **/team**: it shows TWO different font-CSS URLs in the delivered HTML because `AppShell` requests `JetBrains+Mono:wght@400;500;600` and `BrandLoudHero` requests `JetBrains+Mono:wght@400;500;600;700`. Two render-blocking CSS requests for fonts that overlap 90%. Same problem on /, /audit, /cohorts (anything that mounts BrandLoudHero inside AppShell).

Effect on demo: every page does a DNS lookup + TCP handshake + TLS to `fonts.googleapis.com` even though the connection is preconnected, the CSS body parses, then a SECOND request goes to `fonts.gstatic.com` for the actual `.woff2` files. **Audiowide has `font-display: swap`** so it does eventually paint — but in the meantime the hero H1 renders in fallback Inter for 100-500ms (FOUT). On 4G + cold cache, that's 1-2 seconds.

**The fix that closes everything** (single highest-impact fix in this audit, see TL;DR): add Audiowide via `next/font/google` in `app/layout.tsx` next to Inter / JetBrains Mono and delete the 19 individual font-link blocks. The `next/font` plugin self-hosts the fonts at build time, generates preload `<link>` hints in the HTML response (which is already happening for Inter/JetBrains — confirmed in `Link` response header for `/landing`), and eliminates the 3rd-party DNS+TLS overhead. Savings: **2 render-blocking CSS requests × 9 demo pages = 18 fewer roundtrips on the demo path**, plus ~200KB of font bytes that come from self-hosted preload instead of Google's CDN.

### 5. Layout shift (CLS) risk

Three CLS vectors active on the demo path:

**5a. `/compare` flash-of-unstyled-content (the e2e agent's bug)** — this is the *single most demo-damaging issue identified*.

Root cause:

```tsx
// web/app/compare/page.tsx — lines 1, 148-155
"use client";                       // client component, no SSR styling
...
export default function ComparePage() {
  return (
    <>
      <link rel="preconnect" href="https://fonts.googleapis.com" />     // ← inside React tree, not <head>
      <link
        href="https://fonts.googleapis.com/css2?family=Audiowide&family=JetBrains+Mono..."
        rel="stylesheet"
      />
      <style jsx global>{`                                              // ← styled-jsx, injected on hydrate
        .compare-stage { padding: 48px 32px 96px; max-width: 1180px; ... }
        .compare-hero { font-family: "Audiowide", "Inter", sans-serif; font-size: 48px; ... }
        ...
```

The sequence on first paint:

1. Server renders HTML with `class="compare-hero"` but no CSS rules attached (styled-jsx CSS is generated client-side from the React tree)
2. Browser receives HTML — sees no font-family rule, no font-size rule, no padding rule → renders raw `<h1>` in browser default
3. Browser hits the `<link>` for Google Fonts CSS, requests it, parses
4. React hydrates, styled-jsx injects the page-scoped `<style>` block
5. Audiowide arrives, replaces fallback Inter, hero text reflows

This produces the FOUC the e2e agent reported. The headline jumps from 16px serif (browser default) → 48px Inter → 48px Audiowide over ~600ms on a warm connection, longer on cold.

**Recommended one-line fix:** delete `"use client"` from `web/app/compare/page.tsx:1`. The page has zero state. As a server component, Next.js will:
- Inline the styled-jsx CSS in the SSR'd HTML head (no hydration delay)
- Preload the Audiowide woff2 via `next/font` (after applying the next/font Audiowide fix in #2)
- Render the H1 in Audiowide on first paint

Same fix simultaneously solves the same FOUC on `/landing`, `/customers`, `/docs`, `/changelog`.

**5b. `BatchCarousel` and `LazyOverflowMenu` `next/dynamic` without `loading:` prop**

`web/components/skycot/BatchGroupBlock.tsx:19` and `web/components/skycot/WorkerHero.tsx:39` use `dynamic(..., { ssr: false })` with no `loading: () => <Skeleton />`. The result: empty space → component pops in once the chunk loads. `BatchCarousel` is variable-height — this is a real CLS on `/` (Approvals). `LazyOverflowMenu` is a kebab button — micro CLS, not visible on camera.

Fix: `dynamic(..., { ssr: false, loading: () => <CarouselSkeleton height={120} /> })` for BatchCarousel.

**5c. Audiowide font swap on `/landing` hero**

Audiowide is loaded with `display: swap`. So the hero "Hire your first AI teammate" renders in Inter (fallback) for ~100-500ms cold, then swaps to Audiowide. Audiowide is ~2x the character width of Inter at the same font-size, so the H1 reflows.

Fix: once next/font Audiowide lands (#2), set `display: 'optional'` + use `next/font`'s built-in `adjustFontFallback` with a size-adjusted Inter fallback. This either prevents the swap (if fonts are slow) or preloads Audiowide before first paint.

## Other findings worth flagging before demo

**6. `Cache-Control: no-store, must-revalidate` on `/landing` (verified via `curl -I`).** Marketing pages should be `public, s-maxage=300, stale-while-revalidate=86400`. One-line `headers()` config in `app/landing/page.tsx`. Repeat visitors will appreciate this.

**7. The `--purple` / `--pink` / `--ink` / `--bg` design-token CSS block is reproduced verbatim 7 times across page files** (`rg -l '\-\-purple:\s*#8'`). Should live once in `app/globals.css`. Bug-prone and bloats every page.

**8. `/workflows/templates` is 105 KB HTML (2x the median).** The cohort lists + template cards are inlined static data. Could move to a JSON file fetched async OR — easier — to server-component rendering with React Query hydration. Not a demo-blocker but worth noting.

**9. `productionBrowserSourceMaps: process.env.CI === "true"`** in `next.config.ts:13`. Correct default — but worth double-checking that the production host (Vercel?) doesn't set `CI=true` at runtime, which would leak source maps to the public.

**10. CSP allows `'unsafe-inline'` on `style-src` and `'unsafe-eval'` on `script-src`.** Required by styled-jsx + Next.js dev tooling. Worth flagging as P3 to revisit post-demo (CSP nonces).

## Lighthouse-killer risks (would tank a Lighthouse score before demo)

1. **FOUC from client-component marketing pages + non-`next/font` Audiowide → CLS spike + LCP-blocker** (#1, #2, #5a). This is the worst Lighthouse impact in the audit.
2. **`Cache-Control: no-store` on `/landing`** (#6) → 0/100 on "Serve static assets with an efficient cache policy."
3. **Audiowide swap reflows hero** (#5c) → CLS metric.
4. **20 duplicate Google-Fonts CSS requests across the demo path** (#2) → "Eliminate render-blocking resources" + "Avoid third-party request chains."

Items 1, 2, and 4 all resolve with the same fix: **add Audiowide to `next/font/google` in `app/layout.tsx` and delete the 19 redundant `<link rel="stylesheet">` blocks**.

## Methodology

- TTFB / Total / Bytes: `curl -s -o /dev/null -w` on `localhost:3000` against the running Next.js dev server
- Use-client tally: `rg -l '"use client"' web/app/ | wc -l` vs `find web/app/ -name '*.tsx' -o -name '*.ts' | wc -l`
- Zero-state pages: `rg -c 'useState|useEffect|useRouter|useContext|useReducer|useRef|onClick=|onChange=|onSubmit=' <file>`
- Font-link audit: `rg -l 'fonts\.googleapis\.com' web/app/ web/components/`
- Heavy-lib audit: `rg 'from "framer-motion"|from "motion|from "lottie|from "@react-three|chart\.js' web/`
- Delivered-HTML font-link count: `curl -s … | grep -c 'fonts.googleapis.com'`
- Cache-Control header verification: `curl -s -I http://localhost:3000/landing`
- Chunk sizes: `du -k web/.next/static/chunks/*.js | sort -rn | head -15`
- xyflow route scoping: `curl -s … | grep -c 'xyflow'` per route
