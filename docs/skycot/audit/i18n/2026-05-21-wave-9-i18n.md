# Wave-9 Audit: i18n / Localization Readiness

**Date:** 2026-05-21
**Auditor:** Wave-9 audit agent #3 (Claude Opus 4.7)
**Scope:** `~/code/argo/web/` — SKYCOT SPA (Next.js 15 + React 19, 411 .tsx files)
**Verdict:** **NONE — zero i18n infrastructure exists. The product is hardcoded English-only.**

---

## TL;DR

- **No i18n library is installed.** `package.json` has no `next-i18next`, `react-intl`, `i18next`, `@lingui/*`, `next-intl`, or anything equivalent.
- **No translation seam exists.** Zero `useTranslation()`, zero `t("key")`, zero `<Trans>`, zero `formatMessage()` calls in the entire codebase. The single `t(` match (`lib/workflow-templates.ts`) is a local template-row constructor, not a translation function.
- **No locale routing.** `next.config.ts` has no `i18n` config block. The Next.js app router has no `[locale]` segment.
- **Hardcoded `<html lang="en">`** in `app/layout.tsx` line 89. OpenGraph locale also hardcoded `"en_US"` (line 67).
- **No browser-locale detection** anywhere (`navigator.language`, `Accept-Language` header — zero matches).
- **~2,600 hardcoded English string literals** of length 3+ chars in `.tsx`/`.ts` files (excluding `.next/` and `node_modules`). Spot-checked sample-data files (`lib/sample-*.ts`) are pure English prose; UI strings (button labels, headings, placeholders) are inlined in JSX.
- **No RTL support.** 124 physical Tailwind margin/padding classes (`ml-`, `mr-`, `pl-`, `pr-`) vs zero logical equivalents (`ms-`, `me-`, `ps-`, `pe-`). 34 `text-left`/`text-right` (physical) vs zero `text-start`/`text-end` (logical). `globals.css` has no `[dir="rtl"]` selectors and no `margin-inline-start`/`inline-end` logical properties.
- **Currency hardcoded as `$`** across all sample data (`lib/sample-approvals.ts`, `lib/sample-audit.ts`, `lib/sample-worker-overview.ts`, etc.). Zero `Intl.NumberFormat` calls anywhere.
- **Date formatting partially locale-aware by accident** — most `.toLocaleString()` calls pass `undefined` (uses browser default), but two files hardcode `"en-US"`: `lib/api/audit.ts` (month-name extraction) and `components/skycot/audit/ActionSummaryHero.tsx`. Only 2 files use `Intl.DateTimeFormat`-typed options.
- **Pluralization is string-concat / ternary, not ICU.** 18+ instances of `count === 1 ? "fact" : "facts"`-style ternaries spread across components. None of them handle non-English plural rules (Russian has 3 plural forms, Polish has 4, Arabic has 6).

## Minimum Work to Enable Spanish (es-ES)

This is the realistic floor — what it takes to ship a Spanish locale to one enterprise customer in EU/LATAM:

### Phase 1 — Foundation (5–7 dev-days)

1. **Pick a stack.** Recommend `next-intl` (App Router native, SSR-friendly, ICU MessageFormat built-in) over `next-i18next` (pages-router legacy) or `react-intl` (no Next.js routing integration).
2. **Add `[locale]` route segment.** Rewrite `app/layout.tsx` and child layouts to read `params.locale`; set `<html lang={locale}>` dynamically.
3. **Configure Next.js routing.** `middleware.ts` detects `Accept-Language`, redirects `/` → `/en` or `/es`. Persist preference in a cookie.
4. **Extract ~2,600 strings into message catalogs.** Use a codemod (e.g. `i18n-extract` from `next-intl`) to scan JSX text nodes and string literals, emit `messages/en.json`, leave call-sites as `t("key")` references. Realistically 60-70% mechanical, 30-40% manual (interpolation, plurals, context). **Estimate 3–4 dev-days for the extraction pass alone.**
5. **Convert pluralizations to ICU.** Replace all 18+ `count === 1 ? ...` ternaries with `{count, plural, one {# fact} other {# facts}}` ICU strings.
6. **Replace hardcoded `$` with `Intl.NumberFormat`** in sample data and any production currency rendering. Add a `currency` field to approval/audit records.
7. **Replace `"en-US"`-hardcoded date formatters with locale-from-context.**

### Phase 2 — Translation (3–5 dev-days + translator cost)

8. **Get `messages/en.json` translated to `messages/es.json`.** ~2,600 strings × USD $0.10–0.20/word = ~$2,000–5,000 from a professional vendor. Machine-translate first (DeepL / Google), then human-edit for product voice.
9. **Length-test the layout.** Render every page with `messages/es.json` and audit for clipping, wrapping, overflow. German (`de`) is the harder pole — Spanish typically lands within +10–15% length, German is +30–40%.

### Phase 3 — RTL (deferred, 4–6 dev-days when first Arabic / Hebrew customer signs)

10. **Convert 124 physical Tailwind classes to logical** (`ml-2` → `ms-2`, `text-left` → `text-start`).
11. **Add `dir={locale === "ar" ? "rtl" : "ltr"}`** to `<html>`.
12. **Audit icons / arrows / chevrons** for mirroring. Lucide icons need `rtl:rotate-180` on chevrons, arrows, undo/redo.
13. **Audit `motion`/animation directions** — slide-in-from-left becomes slide-in-from-right.

**Total estimate for Spanish-only (Phase 1 + 2):** 8–12 dev-days + ~$2–5k translation cost.
**RTL (Arabic / Hebrew):** add 4–6 more dev-days when the first customer asks.

## Recommended v1 Strategy

The operator's v1.0 strategic decisions lock SKYCOT as **enterprise-focused, Melbourne-built, macOS demo path**. EU/LATAM/APAC enterprise buyers will ask about localization in the first sales call, but won't typically *block* v1 deal on it — they want a **roadmap commitment** more than a shipped feature.

**Recommendation:**
1. **v1.0:** Do NOT localize. Ship as English-only. Document the gap explicitly in `docs/skycot/audit/i18n/` (this report) so the next sales call can answer "yes, we know, here's the plan."
2. **v1.0 prep work (low cost, high option-value):** Convert 124 Tailwind margin/padding classes from physical → logical (`ml-` → `ms-`) — this is a 1-day mechanical refactor that costs nothing today and unblocks RTL when the time comes. Same for `text-left` → `text-start`.
3. **v1.1 or v1.2:** Pick `next-intl`, add the extraction seam, ship `messages/en.json` as the only catalog. This is the load-bearing change — once strings are externalized, adding `es.json` / `de.json` is a 2–3 day project per locale.
4. **v2.x or first paying customer in EU/LATAM:** Ship Spanish + German + (per customer demand) Portuguese / French.
5. **RTL:** Deferred until first Arabic / Hebrew customer.

## Closing Note

This audit confirms: SKYCOT today is structurally English-only. There is no partial seam to extend — the work is greenfield. The good news is that the codebase is small enough (~411 .tsx files, ~2,600 strings) that a single focused brief in v1.1 can land the extraction in ~10 dev-days. The bad news is that without operator commitment, the strings will continue to multiply (every new page adds ~30–80 strings), making the extraction more expensive over time. **Recommendation: lock the externalization decision before v1.1 begins, even if no locale is shipped until v1.2.**
