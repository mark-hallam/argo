# SKYCOT — Feature Matrix & Roadmap (source of truth)

**What this is:** the single, honest inventory of every SKYCOT capability — what's
**real and working**, what's **scaffold**, and what's **planned** (with phase/timeline).
It is the canonical tracker for features + roadmap; other docs link here.

**Last verified:** 2026-05-31 by a parallel **code-grounded audit** (5 agents over
core platform / product surfaces / integrations+channels / agents+verticals+voice /
roadmap); **updated 2026-05-31** for the Genesis P0–P7 (incl. the SOP-upload comprehension moat + the LLM-graded capability rubric) + eval-floor build-out (on
top of the earlier Sprint-2 work: voice V1/V2, settings, evals, governance
readiness, training-data export, retrain-recent — each row cites its commit). Every
row is grounded in a crate, gateway route, SPA module, or doc —
**not** transcribed from roadmap narratives (which drift). Re-verify with `git log`
+ the cited source before trusting any single row. **Caveat carried by several
2026-05-30 rows:** the feature is committed + tested but the *running* gateway is
still the old binary, so it goes live only after the next gateway rebuild
(`scripts/restart-live-gateway.sh --force --no-prompt`).

> **Why the rigor:** this codebase is *more real* than its docs feared (genuine
> hash-chained audit, enforced RBAC, per-tenant MCP pooling, ~8,200 test fns) — but
> it also has scaffold dressed as features (orphan crates, mock-in-demo-live SPA
> surfaces). This matrix draws that line explicitly so we never confuse "code exists"
> with "it works for a user."

## Status legend

| Badge | Meaning |
|---|---|
| ✅ **Live** | Real, wired, verified working end-to-end |
| 🟡 **Partial** | Works with caveats (one direction, mock in some modes, missing sub-piece) |
| 🟧 **Scaffold** | Code exists but **unwired / unusable / stub** (not a working feature yet) |
| 🚧 **In-progress** | Actively being built (brief claimed / partially landed) |
| 🗓️ **Planned** | Designed / brief exists, not built — phase + timeline noted |
| 💡 **Backlog** | Named, not yet scoped |

- **The product is genuinely demo-ready.** All 6 mission claims have real backend +
  real demo surfaces; two AI teammates (Portia, Grant) do real LLM work, truth-bounded,
  approval-gated; audit is a real hash chain; ~30 MCP connectors are real.
- **Biggest honesty gaps (updated 2026-05-31):** (1) **live voice on Zoom/Teams calls = not built** — but the loop beneath it is now real: the L1 trait layer + L2 truth-bounded gateway voice-loop + **real OpenAI adapter (L1b)** are shipped and **live-verified end-to-end** against a real key (P2/DEC-023: TTS→`audio/mpeg`, STT round-trip verbatim, pitch-turn over-claim defers with no `$`). The browser "Talk to Portia" mic UI (L3a) is built + unit-tested, and the reusable `VoiceChat` component seam is now built for hero-console adoption (browser-eyes-on pending). What remains unbuilt is **only the meeting-join layer (L3b)** — Recall.ai / Zoom-SDK / Teams bot; (2) the cluster of mock-in-demo-live SPA pages is **shrinking** — settings/governance-readiness/retrain-recent/audit-export/retros are now **live** (gateway rebuilt + verified 2026-05-30, commit `ccfa89588`); evals is live-but-empty (`skill_reeval_history` not yet seeded — follow-up); Ghostwriter, Skill-IR read/save/export/import, and elevated-view are now frontend-unmocked in demo-live (Node-verified) but runtime gateway behavior remains unconfirmed in this clone; remaining known gaps include api-keys/provider-keys (SKIP-privacy), worker schedules/escalation; (3) the **JSON-RPC plugin ABI** and **teammate-eval scorer** are still tested code with zero live consumers.
