Scene 2 narrates "inside 60 seconds the audit chain has the proof row" while the chain on screen is invented. Worse than an empty state because the viewer would believe it.**

## Root cause

`ActivityRow.tsx:40` links each activity row to `/audit/action/<activity.id>`. The activity ids generated by `web/lib/sample-worker-activity.ts:185-186` use the pattern `act_${workerId}_${i.toString().padStart(3, "0")}`. The SAME pattern is used in `web/lib/sample-audit.ts:134` for `SAMPLE_AUDIT_ROWS`, so `findSampleAuditDetail()` MATCHES every activity-row click and returns `synthesizeAuditDetail(row)` — which fabricates `provenance.skill.id`, `provenance.model.id` (`claude-opus-4-7`), and an 8-stage decisionChain out of static template content with no connection to the original action.

Trace path:

1. `web/components/skycot/ActivityRow.tsx:40` — `<Link href="/audit/action/${activity.id}">`
2. `web/lib/sample-worker-activity.ts:185-186` — id format `act_<workerId>_<padded-index>`
3. `web/lib/api/audit-detail.ts:96-124` — `fetchAuditDetail()` → `findSampleAuditDetail()`
4. `web/lib/sample-audit.ts:134` — same `act_<workerId>_<padded-index>` pattern means a match is FOUND
5. `web/lib/sample-audit-detail.ts:270-276` — `synthesizeAuditDetail(row)` fabricates a populated detail page

Per the function-vs-dressing rule in `docs/skycot/demos/v1-demo-positioning-poc-vs-public.md`: "audit rows the camera DRILLS INTO are from real agent turns" — function-side, NO theatre. Scene 2's drill-in is a function-side beat by definition (the camera follows the click and reads what lands). Today the page reads as agent reasoning that did not happen.

## Fix recipe

Operator preference per memory `feedback_no_theater_in_demo`: real backend seed, not mock-bypass. Three paths — ship the gated theatre flag now (path 2) + author the seed-side follow-up (path 3).

**Path 1: short-term — make the activity-row URL stable but the drill-in honest.**

In `web/lib/api/audit-detail.ts:96-124`, gate the synthesized path:

```ts
function findSampleAuditDetail(actionId: string): AuditDetail | null {
  const hand = SAMPLE_AUDIT_DETAILS.find((d) => d.actionId === actionId);
  if (hand) return hand;

  // Only synthesize from SAMPLE_AUDIT_ROWS in demo+theatre mode.
  if (process.env.NEXT_PUBLIC_ARGO_ALLOW_THEATRE_PROVENANCE === "1") {
    const row = SAMPLE_AUDIT_ROWS.find((r) => r.id === actionId);
    if (row) return synthesizeAuditDetail(row);
  }
  return null;
}
```

Default `NEXT_PUBLIC_ARGO_ALLOW_THEATRE_PROVENANCE` is unset (off) so the demo MP4 sees the honest path. Set to `1` only for storybook / local dev playground.

**Path 2: when the synthesized path is off, return an "Action detail unavailable — drill into another row for full provenance" placeholder (no fabricated chain, no fabricated provenance).** Pair this with the `fix-placeholder-audit-detail-fabricated-decision-chain-and-provenance` brief.

**Path 3: real seed (preferred long-term).** Seed at least one real workflow execution per persona at `argo demo seed` time so the activity tab carries gateway-real audit ids that resolve to gateway-real details. Author a follow-up brief `fix-demo-seed-fire-one-workflow-per-persona` if not already covered by `fix-demo-seed-cli-for-real-roster`.

**Path 4 (alternative, lower-friction): rewrite the runbook to script the operator to fire a real workflow run BEFORE clicking the activity tab, so the row clicked is a real one.** Requires F1/F2 of the Scene 4+5 audit to be fixed first.
