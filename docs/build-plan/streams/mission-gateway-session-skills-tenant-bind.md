🔴 **P1 CLAIM-5/6 CROSS-TENANT LEAK CLUSTER.** 13 gateway routes
under `/sessions/<id>/…` (skill attach/detach/list/clear, lifecycle
end/reopen/title/delete, message append, run/steer, judge,
judge-override) accept a session UUID and drive mutation without
binding tenant ownership. tenant_b with a tenant_a session UUID can
attach skills to tenant_a's session, end it, reopen it, rename it,
delete it, post messages into it, run/steer turns inside it, judge
its content, or flip a judge verdict on it.

## Why

Sibling sweep brief `eval-gateway-uuid-bound-routes-tenant-
ownership-sweep` §3 cluster 6. FINDINGS-ONLY pin
(`pin_cluster_6_session_attach_skill_leaks_across_tenants`) lives at
`crates/argo-cli/tests/gateway_uuid_routes_tenant_ownership.rs`.

**This is the highest-blast-radius cluster** in the sweep:
13 distinct mutations, several of them silent (no audit row
generated by the gateway side until the mutation completes). The
canonical mitigation is the shared session-ownership pre-flight
helper noted in the sweep report §3 cluster 6:

```rust
fn assert_session_belongs_to_tenant(
    store: &SessionStore,
    sid: SessionId,
    tenant_id: &str,
) -> Result<(), (&'static str, String)> // 404 not_found envelope on mismatch
```

Once the helper exists, every route in cluster 6 (and cluster 2's
read-side equivalents) calls it before the mutation. Drop-in pattern;
no per-route SQL rewrites needed.

## Scope

- Add `assert_session_belongs_to_tenant` as a small helper in
  `tenant_header.rs` or as route-local helpers in the touched route
  files. `routes_helpers.rs` does not exist on current main and
  `mod.rs` is already close to the 500-LOC ceiling, so do not add a
  new gateway module in this brief.
- At each of the 13 callsites in cluster 6, derive `tenant_id` via
  `request_tenant_id(req)` and call the helper before invoking
  the mutating store fn. Early-return the 404 envelope on
  mismatch.
- For `judge_override_response` (the one cluster-6 route that
  doesn't take a session UUID — it takes a `judge_record_id`),
  the equivalent helper is `assert_judge_record_belongs_to_
  tenant(store, record_id, tenant_id)`. Implement alongside.
- Un-ignore + invert
  `pin_cluster_6_session_attach_skill_leaks_across_tenants`.
- Add 3 same-tenant baseline regressions (attach + run + delete
  legitimate-tenant paths stay green).
- ~350-500 LOC.
